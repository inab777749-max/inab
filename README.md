# INAB OFFICIAL — 사이트 + 관리자

정적 사이트(HTML/CSS/JS) + Supabase(자료 저장·로그인) 구성.
빌드 도구 없이 파일을 그대로 올리면 동작한다.

---

## 1. 설치 순서

**순서를 지킬 것.** 계정보다 SQL을 먼저 실행하면 쓰기 권한이 잠겨 본인도 저장할 수 없다.

| 순서 | 하는 곳 | 내용 |
|---|---|---|
| 1 | Supabase | New project 생성 → Settings > API 에서 Project URL·anon public key 복사 |
| 2 | Supabase | Authentication > Users > Add user 로 관리자 계정 생성 (**Auto Confirm User 켜기**) |
| 3 | Supabase | SQL Editor 에 `supabase.sql` 전체를 붙여넣고 Run |
| 4 | 파일 수정 | `assets/js/supabase.js` 맨 위 두 줄에 1번에서 복사한 값 입력 |
| 5 | GitHub | 폴더 구조 그대로 업로드 |
| 6 | Cloudflare Pages | Connect to Git → 저장소 선택 → 빌드 설정 비움(Framework = None) → Deploy |

`assets/js/supabase.js` 에서 바꾸는 두 줄:

```js
const SUPABASE_URL  = 'https://프로젝트ID.supabase.co';
const SUPABASE_ANON = 'anon public key';
```

두 줄을 채우기 전까지 사이트는 파일에 들어있는 기본 내용을 그대로 보여준다(오프라인에서도 동작).
채운 뒤부터 관리자에서 고친 내용이 사이트에 반영된다.

---

## 2. 관리자 페이지

주소는 `배포주소/admin/` — 2번에서 만든 이메일·비밀번호로 로그인한다.
비밀번호는 코드에 들어있지 않고 Supabase 가 관리한다. 변경·추가·삭제는 Supabase > Authentication > Users.

| 탭 | 고치는 것 |
|---|---|
| 🔗 공통 | 로고 글자, 상단 메뉴 이름, 푸터 문구·링크, 검색 결과 제목·설명, 공유 미리보기 이미지, **장식 나비 3종·탭 아이콘** |
| 🏠 메인 | 첫 화면 사진·문구·버튼, Selected Works 줄 제목, 하단 3칸 |
| 👤 작가 프로필 | 머리글, 프로필 사진·소개·태그, 협업 작가 목록 |
| 🖼 포트폴리오 | 머리글, 분류 목록, 카드 사진 비율, 작업 목록 |
| 📝 커미션 안내 | 머리글, 진행 과정, 안내사항, **문의서 양식**, 전송 상자 |
| 💰 가격 안내 | 머리글, 분류, 데뷔 패키지, 추가 옵션 표 |
| 📅 작업 일정 | 머리글, 요약 3칸, 달력 연·월, 일정 목록, 하단 안내 |
| 🛍 개인작 판매 | 머리글, 준비 중 화면, 상품 목록 |
| ❓ FAQ | 머리글, 질문·답변 목록 |
| 🎨 테마 | 색 10종(프리셋 5종·읽기 쉬움 검사), 글자 크기 4단 |
| 📮 문의함 | 사이트에서 전송된 문의 열람·삭제 |

동작 규칙

1. 화면 아래 **저장하기**를 눌러야 반영된다. 저장 전에 창을 닫으면 경고가 뜬다.
2. 목록 항목은 **＋ 새로 추가 / ▲▼ 순서 / ✕ 삭제**. ✕ 는 즉시 삭제된다.
3. 사진은 **사진 올리기** 버튼으로 바로 올린다. 올린 파일은 Supabase 저장소(`site-images`)에 들어가고
   주소가 자동으로 채워진다. 다른 곳에 올린 사진이면 주소를 붙여넣어도 된다.
   칸을 비우면 사이트에 들어있는 기본 사진이 쓰인다(**기본 사진으로** 버튼).
   올린 사진은 가로 1800px 이하로 자동 축소·압축되어 저장된다. 각 칸의 **규격** 줄에 권장 크기가 적혀 있다.
4. **백업 내려받기**로 전체 내용을 .json 으로 보관할 수 있고, **백업 불러오기** 후 저장하면 그 시점으로 되돌아간다.
5. 개인작 상품이 한 개도 없으면 개인작 판매 페이지는 자동으로 준비 중 화면이 된다.
6. 목록을 **전부 비우면 그 구간이 화면에서 사라진다**(제목만 남은 빈 구간이 생기지 않음).
   반대로 인터넷·DB 문제로 값을 못 읽으면 파일에 든 기본 내용을 그대로 보여준다.
7. 공유 미리보기 이미지는 디스코드·X에 주소를 붙였을 때 뜨는 사진이다. `https://` 로 시작하는 전체 주소를 넣는다.

## 3. 사진 규격

| 자리 | 권장 크기 | 비율 | 잘림 |
|---|---|---|---|
| 메인 첫 화면 배경 | 1800×1013 | 16:9 가로 | 화면 크기에 맞춰 잘림. 오른쪽에 인물이 오는 사진 권장 |
| 작가 프로필 사진 | 640×640 | 1:1 정사각 | 정사각으로 잘림 |
| 포트폴리오 작업 | 1200×900 | 4:3 가로 | 카드 비율로 잘림. 세로 사진은 “전체 보기”로 |
| 협업 작가 | 816×459 | 16:9 가로 | 이 비율로 잘림 |
| 개인작 상품 | 900×1200 | 3:4 세로 | 이 비율로 잘림 |
| 공유 미리보기 | 1200×630 | 1.91:1 | 잘리지 않음 |
| 메인 첫 화면 나비 | 600×526 | 자유 | 원본 비율 유지 · 배경 투명 권장 |
| 하위 페이지 상단 나비 | 962×1040 | 자유 | 원본 비율 유지 · 배경 투명 권장 |
| 연한 워터마크 나비 | 876×880 | 자유 | 원본 비율 유지 · 배경 투명 권장 |
| 브라우저 탭 아이콘 | 64×64 | 1:1 | 아주 작게 보임 · 단순한 그림 권장 |

올린 사진은 가로 1800px 이하로 자동 축소되고 WEBP 로 압축된다. 원본을 그대로 올려도 된다.

## 4. 포트폴리오 카드 비율

카드 사진은 원본 비율과 상관없이 **모두 같은 비율**로 맞춰진다(기본 4:3, 포트폴리오 탭에서 변경).

| 표시 방식 | 결과 | 쓰는 경우 |
|---|---|---|
| 꽉 채우기 | 카드에 가득 차고 넘치는 부분은 잘림 | 가로형·정사각 사진 |
| 전체 보기 | 사진 전체가 보이고 남는 자리는 같은 사진 흐린 배경 | 세로로 긴 사진, 잘리면 안 되는 사진 |

꽉 채우기에서 얼굴이 잘리면 **초점 세로 %** 를 줄인다(0 = 위쪽 기준).

## 5. 문의서 양식 고치기

커미션 안내 탭 > 문의서 양식 > **질문 목록** 에 한 줄에 하나씩 적는다.

```
라벨 | 종류 | 도움말 | 선택지;선택지
```

| 종류 | 화면 |
|---|---|
| text | 한 줄 입력칸 |
| textarea | 여러 줄 입력칸 |
| select | 고르는 칸 (네 번째 칸의 선택지 사용) |
| file | 파일 선택 (파일은 전송되지 않고 이름만 복사문에 들어감) |

뒤 두 칸은 생략할 수 있다. 예:

```
1. 안내사항 확인 | select | | 예;아니요;상담 필요
4. 방송 정보 | textarea | 활동명, 플랫폼, 데뷔 예정일 등
9. Unity 파일 사용 목적 | text
```

## 6. 권한 (RLS)

| 대상 | 읽기 | 등록·수정·삭제 |
|---|---|---|
| 사이트 내용 전체 | 누구나 | 로그인한 관리자만 |
| `inquiries`(받은 문의) | **관리자만** | 전송은 누구나, 삭제는 관리자만 |
| 사진 저장소 `site-images` | 누구나 | 올리기·지우기는 관리자만 |

anon key 는 공개용이라 숨길 수 없으므로 권한은 브라우저가 아니라 DB(RLS)에서 나눈다.
`supabase.sql` 에 이미 반영되어 있고 여러 번 다시 실행해도 안전하다.

## 7. 파일 구조

```
index.html  profile.html  portfolio.html  commission.html
pricing.html  schedule.html  shop.html  faq.html
admin/index.html
supabase.sql
assets/css/styles.css
assets/js/schema.js  supabase.js  content.js  site.js
assets/images/
```

| 파일 | 역할 |
|---|---|
| `assets/js/schema.js` | 관리자 입력칸과 페이지 항목의 기준 목록. 항목을 늘리려면 여기만 고치면 관리자 화면이 따라 만들어진다 |
| `assets/js/supabase.js` | 접속 정보 두 줄 + 공통 함수 |
| `assets/js/content.js` | DB 값을 읽어 각 페이지를 그림. DB가 없으면 파일에 있는 기본 내용 유지 |
| `assets/js/site.js` | 메뉴·필터·확대보기·탭·문의서 동작 |
| `supabase.sql` | 표 생성 + 권한 + 현재 내용 예시 자료 |

## 8. 다시 배포

바뀐 파일 덮어쓰기 → Commit → 1~2분 대기 → 브라우저에서 **Ctrl+Shift+R**.
관리자에서 고친 내용은 재배포 없이 바로 반영된다(새로고침만 하면 된다).
