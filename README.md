# INAB OFFICIAL — 사이트 + 관리자

HTML/CSS/JavaScript와 Supabase로 구성한 기존 INAB 사이트 수정본입니다. 별도 빌드 없이 폴더 구조를 유지해 배포합니다.

- 공개 사이트: https://inabshop.pages.dev/
- 관리자: https://inabshop.pages.dev/admin/
- 이번 수정: 포트폴리오 슬라이드, 공용 사진·영상 보관함, 작업 일정·예약 정보, 관리자 편집 방식, 글꼴·전환·클릭 효과.

## 1. 기존 사이트 업데이트 순서

이 파일 묶음은 **현재 INAB 프로젝트를 위한 업그레이드**입니다. 새 Supabase 프로젝트에 그대로 설치하는 초기화 패키지가 아닙니다.

1. 기존 배포 파일과 관리자 JSON 백업을 보관합니다. 백업에는 관리용 정보가 포함되므로 공개 저장소·사이트에 올리지 않습니다.
2. 현재 프로젝트의 SQL Editor에서 **inab-revision.sql만 실행**합니다. 기존 자료를 유지하면서 추가 필드, 보관함, 공개 전용 뷰와 관리자 권한을 적용합니다.
3. SQL 성공을 확인한 다음 이 폴더의 수정 파일을 함께 배포합니다. 기존 Cloudflare Pages 설정과 Supabase 연결을 유지합니다.
4. 공개 사이트와 /admin/을 새로고침합니다. 포트폴리오·일정 읽기, 기존 관리자 로그인, 저장 후 다시 불러오기를 확인합니다.

새 공개 페이지는 portfolio_items_public, schedule_events_public 뷰를 사용합니다. SQL 적용 후 구버전 파일이 남으면 구버전의 전체 열 조회가 거부될 수 있으므로 SQL과 파일을 연이어 적용합니다.

**기존 사이트에 supabase.sql이나 supabase-update.sql을 다시 실행하지 않습니다.** 과거 초기화·권한 스크립트는 이번 관리자 제한을 되돌릴 수 있습니다. 오류가 나면 실제 오류와 현재 스키마부터 확인합니다.

assets/js/supabase.js의 프로젝트 주소와 공개용 anon key는 기존 연결을 사용합니다. 비밀번호·service-role key·DB 비밀번호를 파일에 넣지 않습니다. 이번 SQL은 확인된 기존 관리자 사용자 ID에 연결되어 있으므로 다른 계정·프로젝트로 옮길 때는 서버의 관리자 지정도 별도로 변경해야 합니다.

## 2. 관리자 로그인과 저장

/admin/에서는 로그인 화면이 먼저 나옵니다. Supabase Auth 인증과 서버의 inab_is_admin() 확인을 통과한 기존 관리자만 편집 화면과 관리 데이터를 불러옵니다. 로그인한 다른 계정에는 편집 권한이 없습니다.

페이지와 JavaScript 소스 자체는 개발자 도구에서 볼 수 있습니다. 관리자 이메일·비밀번호는 소스에 하드코딩하지 않으며, 실제 권한은 Supabase RLS와 열별 권한으로 제한합니다. 개발자 도구로 화면을 표시해도 서버 권한이 생기지 않습니다.

| 사진·영상 보관함 | 원본 업로드, 검색·분류·태그, 미리보기·사용처 확인 |

### 저장 규칙

- 사이트 설정·작품·일정은 **저장하기**를 눌러 반영합니다. 저장 후 서버에서 다시 불러와 확인합니다.
- 작품·일정 등 목록 삭제는 편집 화면에서 삭제 대기 상태가 되며 **저장하기를 눌렀을 때 서버에 반영**됩니다. 저장 전 새로고침하면 미저장 변경을 버릴 수 있습니다.
- **문의함 삭제는 별도 확인 후 즉시 반영**됩니다.
- 원본 업로드와 보관함 이름·분류·태그 수정은 보관함에 바로 저장됩니다. 파일을 작품에 연결한 내용은 사이트 저장으로 반영합니다.
- 저장 오류가 나면 입력을 유지합니다. 여러 항목을 순차 저장하므로 일부는 이미 반영됐을 수 있으며, 오류를 해결한 뒤 다시 저장합니다.
- **백업 내려받기**는 설정·목록·보관함 메타데이터·날짜별 관리 메모를 JSON으로 받습니다. 원본 이미지·영상 파일은 포함하지 않습니다.
- **백업 불러오기**는 편집 화면을 채우며 저장해야 반영됩니다. 업로드 파일이나 백업에 없는 서버 항목까지 자동 삭제하는 완전 복원 기능은 아닙니다.

## 3. 사진·GIF·영상 보관함

보관함에 한 번 올린 파일은 메인·프로필·포트폴리오·공지·상품 등의 선택창에서 **썸네일로 골라 재사용**합니다. 검색·분류·태그, 큰 미리보기로 파일을 구분합니다. 같은 보관함 파일을 선택하면 기존 URL을 사용하므로 선택할 때마다 다시 업로드하지 않습니다.

새 업로드는 **원본 그대로 저장**합니다. 1800px 축소, WEBP 변환, 자동 압축을 하지 않습니다. GIF·움직이는 WEBP·APNG도 원본 움직임을 유지합니다. 영상은 코덱 변환을 하지 않으므로 MP4/WebM 등 브라우저가 재생 가능한 형식을 사용합니다.

기존 저장소 파일과 이미지 주소는 마이그레이션에서 보관함에 등록하며 이동·재압축하지 않습니다. 과거에 이미 축소되어 저장된 사진의 원래 화질을 자동 복원하지는 않습니다.

공개 페이지에서 사용하는 이미지 URL은 공개됩니다. 비공개 사진 보관용으로 쓰지 않습니다. 외부 이미지 주소도 가능하지만 외부 서비스가 주소를 만료·차단하면 보이지 않을 수 있으므로 계속 사용할 파일은 보관함에 올리는 편이 안정적입니다.

| 자리 | 표시 방식 |
|---|---|
| 메인 대표 이미지 | 기존 구도 유지. 화면 비율에 따라 일부 잘릴 수 있음 |
| 프로필 | 기존 프로필 영역 비율에 맞춰 표시 |
| 포트폴리오 슬라이드 | 같은 높이의 중앙 무대 안에 원본 전체 표시. 세로 사진도 늘이거나 자르지 않음 |
| 공지 사진 | 원본 비율 유지, 확대 가능 |
| 공유 미리보기 | 권장 1200×630. https://로 시작하는 공개 이미지 주소 |
| 나비 장식 | 원본 비율 유지. 투명 배경 권장 |
| 탭 아이콘 | 정사각형의 단순한 이미지 권장 |

권장 규격은 준비 기준이며 업로드 파일을 그 규격으로 강제 변환하지 않습니다.

## 4. 포트폴리오 보기와 편집

공개 포트폴리오는 **전체 / 분류 필터 → 중앙 사진 → 하단 설명** 구조입니다. 세로·가로 사진을 넘겨도 무대와 설명 영역의 높이를 유지합니다. 좌우 화살표, 드래그·터치 스와이프, 키보드 방향키, 하단 진행 막대로 이동합니다. 사진을 누르면 확대되고, 여러 장은 썸네일이나 확대 화면 화살표로 넘깁니다. 동영상은 재생 조작과 확대 버튼을 구분하며 움직임 줄이기 설정도 반영합니다.

등록된 작품명·설명·크레딧·작업일을 하단에 표시합니다. 의뢰자는 서버가 만든 **첫 글자와 별표 두 개로 가린 client_display**만 표시합니다. 관리용 client_name 원문은 공개 페이지에서 읽거나 표시하지 않습니다.

관리자는 상단 분류로 좁히고 **왼쪽 작품 선택 → 오른쪽 편집**을 합니다. 추가·복제·위아래 순서 변경·삭제가 가능합니다. 새 작품과 복제본은 기존 방식대로 맨 위에 생기며 저장된 목록 순서가 공개 사이트 순서입니다. 분류 숫자는 해당 작업 수입니다.

상단 포트폴리오 메뉴는 페이지로 바로 연결합니다. 작품 이름이 계속 늘어나는 메뉴 드롭다운은 사용하지 않습니다. 분류는 포트폴리오 페이지 안에서 고릅니다.

첫 사진은 대표 이미지입니다. 기존 카드 표시 방식·초점 설정은 메인 등의 카드 영역에서 사용하며, **중앙 슬라이드는 항상 전체 보기**입니다.

## 5. 작업 일정과 월별 슬롯

공개 화면과 관리자 모두 패키지 / 닐로툰·뚜따 달력을 구분합니다. 이전·다음 달, 이번 달, 연·월 선택으로 원하는 달을 봅니다. 첫 달은 관리자 설정의 자동 현재 월 / 지정 월을 따릅니다.

- 달력 칸에는 날짜, 휴일·마감 상태와 작업 수 하트를 표시합니다. 긴 작업명은 칸 안에 넣지 않습니다.
- **대기중은 보라색, 작업중은 핑크색, 완료는 청회색**입니다. 작업 개수를 지정하면 그 수가 반영됩니다.
- 공개 화면에서 날짜를 누르면 달력 아래에 **상태·가린 예약자·작업 내용·기간**이 표시됩니다.
- 관리자에서는 날짜 클릭 후 오른쪽에서 하루 여러 작업, 시작·종료일, 개수, 공개 작업명, 관리용 예약자·메모를 수정합니다.
- Ctrl(Mac은 ⌘) 클릭은 날짜 추가·해제, Shift 클릭은 기간 선택입니다. 선택한 날짜에 상태나 작업을 일괄 지정할 수 있습니다.
- 일요일 정기 휴일, 날짜별 휴일·마감·접수 가능 상태, 예약 공지를 설정합니다.

달력 옆에는 예약 공지와 월별 **패키지 슬롯**이 표시됩니다. 관리자가 월·전체 슬롯·예약 슬롯·접수 상태·안내를 입력합니다. 슬롯은 수동 설정값으로 일정 수와 자동 합산되지 않습니다. 공개 영역은 선택한 달부터 최대 3개월분의 등록된 패키지 슬롯을 표시합니다.

예약자 원문·작업별 관리 메모는 관리자용 열에, 날짜 전체의 메모는 schedule_day_private에 저장합니다. 공개 뷰에는 포함하지 않습니다. **공개 작업명·공개 안내에 개인 연락처나 비공개 메모를 적지 않습니다.**

## 6. Social·접수 안내·문의서

메인 관리자의 Social 설정에 실제 **아트머그, X/Twitter, Discord 초대 주소**를 입력합니다. 확인되지 않은 주소는 임의로 만들지 않고 비워 둡니다. 주소가 없거나 서비스 도메인과 맞지 않으면 해당 버튼은 이동하지 않습니다.

커미션 안내의 접수 상태·상단 알림에서 마감 안내와 전 페이지 알림 띠를 설정합니다. 링크 문구와 주소를 모두 채우면 링크가 표시됩니다. 접수 마감 시 문의서 대신 마감 안내가 나옵니다.

현재 클라이언트 방식의 디스코드 웹후크 설정은 공개 사이트 설정에 포함되므로 **사용하지 않고 비워 둡니다**. 웹후크 URL·비밀키를 공개 설정에 저장하지 않습니다. 비공개 서버 알림 기능을 연결하기 전에는 관리자 문의함으로 확인합니다.

문의서 질문은 한 줄에 하나씩 아래 형식입니다.

    라벨 | 종류 | 도움말 | 선택지;선택지
    1. 안내사항 확인 | select | | 예;아니요;상담 필요
    4. 방송 정보 | textarea | 활동명, 플랫폼, 데뷔 예정일 등
    9. Unity 파일 사용 목적 | text

text는 한 줄, textarea는 여러 줄, select는 선택 항목입니다. file 항목은 파일 이름만 문의 복사문에 포함하며 파일 자체를 전송하지 않습니다.

가격 안내의 옵션은 같은 **묶음 이름**끼리 붙이면 소제목으로 묶입니다. 묶음 이름을 비우면 소제목이 없습니다. 개인작 상품이 없으면 판매 페이지에 준비 중 안내가 나옵니다.

## 7. 데이터 권한

| 대상 | 공개 방문자 | 지정된 기존 관리자 |
|---|---|---|
| 공개 설정·공지·가격 등 | 읽기 | 읽기·수정 |

## 8. 주요 파일과 다시 배포
